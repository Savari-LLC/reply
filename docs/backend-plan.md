# Reply MVP backend plan

**Branch:** `codex/mvp-backend`

**Estimated effort:** 4–5 hours

**Primary directory:** `packages/backend/convex/**`

## Mission

Provide persistent, reactive demo data and every state change required by the Northstar story. Do not modify the web application on this branch.

## Scope boundaries

- Use one global demo dataset with no user, membership, or workspace tables.
- Treat sending as a simulated outbound message.
- Seed the Northstar company profile instead of calling Context.dev.
- Return a deterministic canned draft instead of calling a paid AI service.
- Keep the existing authenticated Context.dev action protected.
- Do not weaken or remove its identity check.

## File ownership

The backend developer owns:

- `packages/backend/convex/schema.ts`
- New Convex functions and tests under `packages/backend/convex/**`
- `packages/backend/convex/_generated/**` when regenerated by Convex

The backend developer must not modify:

- `apps/web/**`
- `packages/ui/**`
- Frontend fixture or adapter files

This boundary keeps the backend and frontend branches merge-disjoint.

## Frozen shared contract

Do not rename these values or functions without notifying both other developers before implementation continues.

### Enumerations

```ts
type ThreadStatus = "open" | "waiting" | "closed";
type ThreadPriority = "normal" | "urgent";
type MessageDirection = "inbound" | "outbound";
```

### Figma-informed vocabulary

The backend contract remains product-oriented even when the UI follows the Figma wording:

| Backend value | UI label |
| --- | --- |
| `open` | Open |
| `waiting` | Waiting |
| `closed` | Done |
| Missing `assigneeId` | Unassigned |

Inbound messages render as full email cards and outbound messages render as team replies, so every message must preserve its `direction`. The Figma reference also reinforces the need for nullable assignment, priority, labels, unread state, and a stable latest-message timestamp.

Do not add tables or fields for the reference design’s attachments, files, personal inboxes, multiple email accounts, snoozing, or internal comments.

### Public functions

| Convex function | Kind | Arguments | Purpose |
| --- | --- | --- | --- |
| `demo:getState` | Query | `{}` | Return whether seed data exists and the Northstar thread ID when available |
| `demo:ensureSeeded` | Mutation | `{}` | Idempotently create all demo records and return the Northstar thread ID |
| `inboxes:list` | Query | `{}` | Return inboxes with unread counts |
| `teammates:list` | Query | `{}` | Return assignable demo teammates |
| `threads:list` | Query | `{ inboxId?: Id<"inboxes"> }` | Return thread summaries sorted by most recent message |
| `threads:get` | Query | `{ threadId: Id<"threads"> }` | Return the complete thread, messages, assignee, and company profile |
| `threads:assign` | Mutation | `{ threadId, teammateId }` | Change the thread assignee |
| `threads:setStatus` | Mutation | `{ threadId, status }` | Change the thread status |
| `threads:setUnread` | Mutation | `{ threadId, unread }` | Change the unread state |
| `threads:setPriority` | Mutation | `{ threadId, priority }` | Change the priority |
| `threads:setLabels` | Mutation | `{ threadId, labels }` | Replace the label string array |
| `threads:sendReply` | Mutation | `{ threadId, body }` | Append an outbound message and move the thread to Waiting |
| `drafts:generateDemo` | Query | `{ threadId }` | Return an editable canned draft grounded in the seeded thread |

### Result requirements

`inboxes:list` returns:

- `_id`
- `name`
- `slug`
- `displayOrder`
- `unreadCount`

`teammates:list` returns:

- `_id`
- `name`
- `initials`
- `avatarUrl`, nullable
- `role`

`threads:list` returns:

- `_id` and `inboxId`
- Customer name, email, and sender domain
- Subject and latest-message preview
- Status and priority
- Assignee summary, nullable
- Label string array
- Unread state
- Last-message timestamp

`threads:get` returns the thread summary fields plus:

- Ordered message history
- Company profile, nullable

`drafts:generateDemo` returns:

```ts
{
  source: "demo";
  text: string;
}
```

## Implementation sequence

### B0: Contract milestone

Target: first 30–45 minutes.

- Define schema tables, validators, and indexes.
- Add public function stubs or initial implementations using the frozen names.
- Regenerate Convex types.
- Commit this milestone separately.
- Notify the integration developer that the contract commit is ready.

Suggested commit message:

```text
feat(backend): establish inbox MVP contracts
```

This early commit lets the integration branch compile against real generated APIs while backend implementation continues.

### B1: Idempotent demo data

- Seed Sales, Accounts, and Support.
- Seed three or four teammates.
- Seed approximately 6–10 realistic threads.
- Make Northstar the urgent, unread, most recent Sales thread.
- Seed Northstar messages and company profile.
- Use stable seed keys so repeated setup creates no duplicates.

### B2: Read APIs

- Implement demo-state, inbox, teammate, thread-list, and thread-detail queries.
- Sort inboxes by display order.
- Sort threads by `lastMessageAt` descending.
- Sort messages by `sentAt` ascending.
- Return `null` for missing optional profile or assignee values.

### B3: State mutations

- Validate every referenced thread, inbox, and teammate.
- Implement assignment, status, unread, priority, and labels.
- Trim labels and remove duplicate or empty values.
- Return useful errors for invalid records or values.

### B4: Simulated reply and draft

`threads:sendReply` must atomically:

1. Trim and validate the body.
2. Insert one outbound message.
3. Update the thread preview.
4. Mark the thread as read.
5. Set status to `waiting`.
6. Update `lastMessageAt`.

`drafts:generateDemo` must:

- Confirm that the thread exists.
- Return a deterministic draft appropriate to Northstar.
- Avoid paid or network services.
- Leave editing and sending to the frontend.

### B5: Tests and handoff

Cover at minimum:

- Seed idempotency
- Correct thread and message sorting
- Rejection of an unknown teammate
- Status, priority, label, and unread changes
- Empty reply rejection
- One inserted reply and a resulting Waiting status
- Persisted company context

Run from the repository root:

```bash
bun run check-types
bun run test
```

## Handoff contract

Before declaring the backend branch ready:

- Push the B0 contract commit early.
- Send the integration developer the commit hash.
- Report any unavoidable contract difference immediately.
- Include generated Convex files in the backend branch only.
- Avoid rebasing after the integration branch has merged the branch.
- Finish with a clean backend test and type-check result.

## Exit criteria

- A fresh database can initialize itself through `demo:ensureSeeded`.
- Repeated initialization creates no duplicates.
- Every Northstar state change survives refresh.
- The complete frozen public API is available.
- Backend tests and type checking pass.
- No unauthenticated paid call exists.
